The flow

Every question up front. Every claim backed by evidence.

/sw:ship sizes the task (tiny, small or large) and runs the stages that size needs. You approve the design and the plan. After that Shipwright works through to the PR without pausing, and logs every judgment call as a Ruling.

discover

Code map via CodeGraph. Parallel research: context7 docs, current practices, real repos.

architect

One question at a time: data model, contracts, races, cache, authz, rollout.

plan

Exact files, signatures and named tests. Red-teamed when large.

worktree

.worktree/ with its own DB, Redis db and port.

build

Tiered TDD, with one subagent per task on large work.

verify

Lint → types → unit → integration → coverage → build → dev server → smoke → Playwright.

review

One Opus pass over the whole branch with security and performance lenses.

llms-txt

Client-facing docs synced with every feature.

pr

1–3 commits. PR → base (kept open) and PR → develop.

verify-dev

After merge and deploy, a smoke test on the dev domain, with logs on failure.

continuous After the plan is approved, the only stops are destructive actions, security-sensitive steps, shared side effects (merge, push, deploy), a broken plan, or failed retries.
Features

Built for teams that ship backends

NestJS, Prisma, Postgres and Redis first, with Go and frontend as first-class citizens.

🧭

Architecture interview

A checklist of 12 areas, asking only what the code doesn't already answer. Every question comes with a recommended option. You compare 2–3 approaches, and the result is written to design.md as an ADR.

🔬

Real research

Cheap Haiku researchers run in parallel over library docs (context7), recent practices and gh search code prior art. The output is one page, with sources.

🌿

Worktrees that really isolate

APFS-cloned node_modules. A Postgres DB cloned from yours, schema-only when the source is over 100 MB. A dedicated Redis db and a free port. All of it is dropped on cleanup.

🧪

Tiered TDD

Domain logic and bug fixes are test-first. Endpoints get integration tests against the real DB. Config and DTOs need no test-first. Coverage is gated on the files you changed.

🚦

Runtime verification

Boots the dev server and calls every changed endpoint, covering the happy path and each error case. Frontend flows run headless in Playwright, and the PR gets re-runnable curl lines.

🛰️

Post-deploy check

Waits for your develop PR to merge, then smoke-tests on the dev domain with real auth and reads logs through your MCP on failure. Feature bugs are fixed automatically.

🛡️

Guard rails

Asks before secrets are read. Never searches node_modules. Auth bypasses for smoke tests are snapshotted, and commit and push are blocked until every bypass is restored.

🪶

Token-lean by design

No per-prompt hooks. A bootstrap under 1 KB. About 4 K characters of always-loaded descriptions. References load on demand and subagent replies are capped.

📚

llms.txt every time

Integrators get docs that describe behavior, relations and error codes rather than field dumps. The docs are validated against llmstxt.org.

Quick start

Three commands to your first ship

1 · install

Add the marketplace and install the plugin, then restart Claude Code.

claude plugin install sw \
  --marketplace jamesngdev/shipwright
2 · setup

Once per machine for local Postgres/Redis and your logs MCP. Once per repo for the dev/prod domains.

/sw:setup
/sw:init
3 · ship

Describe the change. Answer the architecture questions, approve the plan, then grab a coffee.

/sw:ship "rate-limit the
  login endpoint per IP"
